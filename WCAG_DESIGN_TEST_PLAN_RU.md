# План: скилл `wcag-design-test`

Дата: 2026-11-06 · Пак: `design` · Статус: черновик плана

## 1. Что делает

```
/wcag-design-test <figma-url-с-node-id> [--level AA|AAA] [--lang ru|ro|en] [--no-annotations]
```

Дизайнер присылает ссылку на frame. Скилл проверяет его по WCAG 2.2 и **рядом с frame** (справа, на том же canvas) создаёт frame `WCAG Report — <имя frame>`:

```
┌─────────── WCAG Report — HomePage Desktop ────────────────────────┐
│ WCAG 2.2 AA · 2026-11-06 · 7 критичных · 5 серьёзных · 4 советов   │
├──────────────────────────┬────────────────────────────────────────┤
│  Уменьшенный снимок      │  ① 1.4.3 Contrast (Minimum) — Критично │
│  frame с номерами        │  Слой: Hero / Container / Subtitle     │
│  ①②③ на проблемных       │  Сейчас: #9CA3AF на #FFFFFF = 2.54:1   │
│  элементах               │  Нужно: ≥ 4.5:1                        │
│                          │  Исправить: #6B7280 (токен gray-500)   │
│                          │  → 4.83:1                              │
│                          │  ② 2.5.8 Target Size — Серьёзно …      │
├──────────────────────────┴────────────────────────────────────────┤
│ Проверить в браузере (в Figma не проверяется): клавиатура, фокус, │
│ screen reader, zoom 200 %, reflow 320px, анимации …               │
│ Пройдено: 1.4.1, 1.4.11, 2.4.6 …                                  │
└───────────────────────────────────────────────────────────────────┘
```

Плюс, по умолчанию, Figma-аннотации категории `WCAG` на самих проблемных слоях (видны в Dev Mode разработчику; визуально frame не меняют) и копия отчёта в `.wpaikit/wcag/<frame-slug>.md` для handoff.

**Главное ограничение:** исходный frame не изменяется. Новые узлы — только report-frame (+ аннотации). Повторный запуск заменяет старый отчёт и обновляет аннотации, не плодя дубликаты.

## 2. Что проверяется

Три группы, и в отчёте они явно разделены — скилл не выдаёт непроверенное за проверенное.

### A. Механически (read-only `use_figma` скрипт, детерминированно)

| WCAG | Проверка | Порог AA (AAA) |
|---|---|---|
| 1.4.3 / 1.4.6 | Контраст текста к ближайшему сплошному фону, с учётом opacity слоёв и полупрозрачных fill | 4.5:1 / 3:1 крупный (7:1 / 4.5:1) |
| 1.4.11 | Контраст не-текста: границы input/checkbox, иконки-кнопки, индикаторы состояний, фокус-обводки | 3:1 к соседнему цвету |
| 1.4.1 | Ссылки в тексте отличаются только цветом (нет underline и контраст к окружающему тексту < 3:1) | — |
| 2.5.8 / 2.5.5 | Размер интерактивных целей (`Button`, `Link`, `Icon Button`, `Input`, `Checkbox`… по имени и по компоненту) | 24×24 или отступ (44×44) |
| 2.4.7 / 2.4.11 / 2.4.13 | У интерактивного компонента есть вариант `Focus`/`Focused`; контраст и толщина фокус-индикатора | есть, ≥3:1, ≥2px |
| 1.4.12 | Line-height < 1.5 для body, letter-spacing; текст с фиксированной высотой (обрежется при spacing override) | advisory |
| 3.3.2 | Input без видимого label (только placeholder) | — |
| 1.4.5 | Растровые изображения, внутри которых текст (по имени/OCR скриншота — см. группу B) | — |
| — | Шрифт < 12px, body < 16px (не критерий WCAG, best practice) | advisory |

### B. Визуально (скриншот + суждение модели, с указанием «оценено по скриншоту»)

- 1.4.3 текст **на изображениях и градиентах** (скрипт не считает — см. Spike в Этапе 0);
- 1.3.1 / 2.4.6 иерархия заголовков: визуальные уровни vs Text Styles (H1 один, уровни без пропусков) — в отчёте предлагаемая разметка `h1…h3`;
- 1.3.2 порядок чтения: порядок слоёв vs визуальный порядок;
- 1.3.3 / 1.4.1 инструкции «нажмите зелёную кнопку», ошибки только цветом;
- 3.3.1 / 3.3.3 есть ли состояние ошибки у форм и понятный текст;
- 2.2.2 у карусели/автоплея виден pause/stop; 2.3.1 мигание;
- 2.5.7 drag-only элементы (слайдер диапазона) без альтернативы кнопками;
- 3.2.3 / 3.2.4 консистентность навигации и иконок между frame'ами, если прислано несколько;
- 1.1.1 какие изображения декоративные, какие нужен alt — список для handoff;
- 1.4.10 есть ли мобильный frame (без него reflow не проверен — так и пишем).

### C. Не проверяется в Figma → чек-лист «Проверить в браузере»

Клавиатурный порядок и ловушки (2.1.x, 2.4.3), accessible names и ARIA (4.1.2), объявления screen reader (4.1.3), zoom 200 % и реальный reflow, `prefers-reduced-motion`, тайминги, skip-link, `lang`. Чек-лист привязан к конкретным элементам frame, а не общий, и ссылается на `better-accessibility` для проверки уже свёрстанного блока.

## 3. Формат одного замечания

Каждое замечание — объект (общий для report-frame, аннотации и `.md`):

```json
{
  "n": 1,
  "criterion": "1.4.3",
  "title": "Contrast (Minimum)",
  "level": "AA",
  "severity": "critical | serious | moderate | advisory",
  "source": "lint | screenshot",
  "nodeId": "123:456",
  "layerPath": "Hero / Container / Subtitle",
  "observed": "#9CA3AF на #FFFFFF = 2.54:1",
  "required": "≥ 4.5:1",
  "fix": "Заменить на токен gray-500 (#6B7280) → 4.83:1",
  "bbox": { "x": 120, "y": 340, "w": 480, "h": 28 }
}
```

Severity: **critical** — провал критерия A/AA на основном контенте или действии; **serious** — провал AA на второстепенном элементе; **moderate** — пограничное (≤0.3 от порога) или вероятный провал по скриншоту; **advisory** — AAA и best practice. Совет к исправлению обязателен и конкретен.

**Подбор исправления цвета (детерминированно):** сначала ближайший по ΔE токен из Variables файла / `.wpaikit/design-system.json`, проходящий порог; если такого нет — тот же оттенок (HSL/OKLCH) с минимальным сдвигом lightness до порога. Скрипт возвращает готовые hex и ratio, модель их не придумывает.

## 4. Как появляется отчёт рядом

1. `get_metadata` / `use_figma`: проверить, что node-id — FRAME/COMPONENT/SECTION; если в ссылке нет node-id — спросить, какой frame.
2. Снимок: `exportAsync` frame в PNG (scale подбирается так, чтобы ширина ≈ 600px) → `figma.createImage(bytes)` → fill прямоугольника внутри report-frame. Номера ①②③ — кружки поверх снимка по `bbox × scale`. Исходный frame не трогается.
3. Позиция: `x = frame.x + frame.width + 200`, `y = frame.y`; если место занято другим узлом — сдвиг вниз до свободного.
4. Report-frame на Auto Layout, ширина 1400px, шрифт Inter (fallback — первый доступный в файле), без зависимостей от DS файла. Маркер для повторного запуска: `setSharedPluginData('wpaikit', 'wcag-report-for', frameId)` (`setPluginData` через MCP недоступен — см. §9).
5. Аннотации: встроенная категория Figma `Accessibility` (есть в каждом файле); если её удалили — создать `Accessibility` через `figma.annotations.addAnnotationCategoryAsync`. `labelMarkdown` с номером, критерием и исправлением; повтор — обновить, не дублировать; устаревшие (проблема исправлена) — удалить.
6. Ответ в чате: краткое резюме + ссылка на report-frame (node-id) + путь к `.md`.

Большие frame'ы: `figma.createImage` падает, если сторона > 4096px (проверено: 4096 — ок, 4100 — «Image is too large»). Scale снимка = `min(600 / width, 4096 / height)`; если при этом ширина < 300px — снимок режется на части по высоте (каждая ≤ 4096px). Замечаний > 40 — группировка однотипных («12 текстов #9CA3AF на белом → один fix»).

## 7. Риски

- **Текст на фото/градиентах** — решено в Этапе 0 (§9): градиенты — по худшему stop, фото — пиксельный замер через временный probe-frame. Остаток риска: фон собран из нескольких слоёв-соседей (не fill предка) — до реализации «стека фона» такие случаи идут в группу B с пометкой «оценено по скриншоту».
- **Вложенная прозрачность и blend modes** — считаем композитный цвет по цепочке родителей; при `blendMode ≠ NORMAL` → в ручную проверку.
- **Распознавание интерактивных элементов по именам** — дополнительно по main component и наличию вариантов `State`; что не распознано — не утверждаем.
- **Перегруз отчёта** — группировка однотипных, лимит карточек, остальное в `.md`.
- **Права на запись** — если файл view-only, отчёт только в `.md` + чат, без падения.

## 8. Решения по умолчанию (можно поменять)

1. Уровень — **WCAG 2.2 AA**, AAA по флагу (AAA-пункты при AA показываются как advisory).
2. Отчёт — **report-frame рядом + аннотации + `.md`**; `--no-annotations` отключает аннотации.
3. Язык отчёта — язык разговора, `--lang` переопределяет.
4. Режима авто-исправления в v1 нет. Кандидат на v2: `--fix` — применяет исправления на копии frame (как `prep-figma` на странице «Dev Ready»), оригинал не трогает.
5. Если прислано несколько frame'ов (desktop + mobile) — один общий отчёт + проверки консистентности 3.2.x.

### Spike (а): контраст текста на изображении — решён

Среда плагина: нет `DecompressionStream`, `TextDecoder`, `WebAssembly`. Есть `exportAsync`, `createImage`, `Uint8Array`.

| Метод | Как | Broken (ожидается провал) | Clean (скрим 0.75, ожидается ≈8:1) | Вердикт |
|---|---|---|---|---|
| 1. Probe-frame | Временный frame размером с bbox текста (clip) + прямоугольник с fills фона, `exportAsync` PNG → inflate на чистом JS (~60 строк) → контраст по каждому пикселю → `min / p5 / median` | 1.02–1.16:1 ✅ | 8.00–8.49:1 ✅ | **Берём.** 30–100 мс на текст (первый вызов ~600 мс). Probe создаётся вне canvas (−100000) и удаляется в `finally`; аудируемый frame не трогается |
| 2. Экспорт с текстом | Экспорт исходного блока, исключение пикселей «похожих на цвет текста» | 0 пикселей фона — светлый фон неотличим от белого текста ❌ | min 1.21 из-за сглаживания краёв ❌ | Отвергнут |

Дополнительно:
- **Градиенты** не требуют пикселей: худший stop против цвета текста (Broken: 1.04–1.25:1).
- **Полупрозрачный скрим поверх фото** даёт детерминированную нижнюю границу без экспорта: скрим поверх белого и поверх чёрного (Clean: ≥ 7.95:1). Пиксельный замер нужен, только если граница не решает вопрос.
- В отчёте используем `p5`, а не `min`: один шумный пиксель не должен валить проверку. При `p5` < порога — провал, при `min` < порога ≤ `p5` — moderate «частично нечитаемо».
- **Ограничение:** метод 1 копирует только fills ближайшего предка. Если фон — соседний слой (фото-прямоугольник под текстом в frame без auto layout), нужен «стек фона»: клон ближайшего общего контейнера без текста и слоёв над ним. Делается в Этапе 1; до этого такие случаи идут в группу B.

### Что поменялось по ходу

### Ограничения, важные для Этапов 3 и 6

- **Интерактивные элементы находятся по именам слоёв.** Контролы с именами `Frame 12` lint не видит. SKILL.md должен сравнивать скриншот со списком найденных целей и честно писать «не проверено, назовите слои», а не «пройдено».
